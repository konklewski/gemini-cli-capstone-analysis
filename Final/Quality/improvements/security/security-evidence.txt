new audit. This targets an availability risk at a concrete dependency. If the
report previously selected only security integrity, add availability with a
project-specific justification rather than describe a crash as an integrity fix.

must not be presented as proof that its server vulnerability is reachable.

Classification warning
Do not simply call every Vitest finding development-only. Although Vitest is
a devDependency in the root/core/cli manifests, packages/test-utils declares
Vitest in dependencies, and it remains in this root production-graph audit.
The package manifest and unchanged baseline lockfile establish that declaration;
the full and omit-dev audit JSON preserve the affected dependency nodes.

Proposal and re-evaluation boundary
No npm audit fix, forced upgrade, dependency edit, or after-fix audit was run.
Use separate reviewed updates, preserve the lockfile, assess reachability and
compatibility, rerun the affected tests, then capture full and omit-dev audits
again. Record justified exceptions with an owner and review date. Rejecting new
high/critical findings in CI is a proposed policy, not an existing measured fix.
The advisories were captured from GitHub's public advisory API as raw JSON.
