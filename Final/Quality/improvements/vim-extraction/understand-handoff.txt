Get the exact versions without changing an existing Gemini CLI checkout
1. Download/copy this entire vim-extraction folder, including its Git bundle.
2. Open a terminal in a NEW working directory and set the folder's real path:
     VIM_EVIDENCE="/absolute/path/to/vim-extraction"
3. Create a new baseline clone:
     git clone --depth 1 --branch v0.64.0 --single-branch https://github.com/google-gemini/gemini-cli.git gemini-vim-before
4. Verify and fetch the incremental bundle. The original baseline is its
   prerequisite, so complete the clone first:
     git -C gemini-vim-before bundle verify "$VIM_EVIDENCE/vim-extraction.bundle"
     git -C gemini-vim-before fetch "$VIM_EVIDENCE/vim-extraction.bundle" 1820eca22b026d6f16c05cc62e845c849aa2f49c:refs/heads/experiment/vim-extraction
5. Select the controlled before version and create a separate after worktree:
     git -C gemini-vim-before switch --detach 8f0a0f2d7d827d7ccd11c3df89631c39af67296f
     git -C gemini-vim-before worktree add --detach ../gemini-vim-after 1820eca22b026d6f16c05cc62e845c849aa2f49c
6. Verify the two revisions:
     git -C gemini-vim-before rev-parse HEAD
     git -C gemini-vim-after rev-parse HEAD

Interpretation
The experiment is function decomposition. It does not remove decisions from
the movement algorithm or resolve the existing import cycle. A smaller outer
function is a local analyzability benefit with an added function-call boundary.
Cyclomatic totals need care when the number of functions changes, because the
metric includes a base contribution per function. Do not claim a reduction in
total behavioral complexity merely because handleVimAction becomes simpler.
Do not compare these Understand measurements with physical source spans or
with a complexity value produced by another tool as if definitions matched.
