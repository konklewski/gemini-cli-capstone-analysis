Config tool-assembly proposal

Baseline: Gemini CLI v0.64.0, 4a0749aceac5643e6f85a36d7420314d85e13b52.
Status: proposed, not implemented.

Config has 109 direct dependencies in the saved dependency-cruiser 18.6.0
report. The inventory finds 27 concrete tools across 21 modules. Twenty
imports could move out; ripGrep.ts stays because getRipgrepPath() still
calls resolveRipgrepPath() (config.ts:2203-2215).

Move to tools/builtin-tool-assembly.ts:
- ToolRegistry and concrete-tool construction.
- Allow-list matching, feature gates and registration order.
- Grep/RipGrep selection, including fallback logging and telemetry.
- Tool discovery and sorting.
- ActivateSkillTool replacement/removal, including initial discovery
  (config.ts:1547-1553) and skill reload (3733-3744).

Config keeps settings, authentication, workspace/session lifecycle, discovery
sequencing, registry access and ripgrep-path caching. The assembly receives
Config and MessageBus. A type-only Config import avoids an emitted import,
but does not remove the runtime dependency on Config methods.

If exactly 20 imports move and one assembly import is added, Config's count
would be 109 - 20 + 1 = 90. This is an estimate, not a measured result or a
reduction in whole-system coupling.

Validation: preserve config.test.ts coverage for createToolRegistry (1515),
ripgrep fallback (2374-2452) and reloadSkills (4056). Check tool names/order,
feature gates, fallback behaviour and skill-tool replacement. Then rerun
dependency-cruiser and compare with the saved report.

Recreate the inventory from the analysis repository root:
  node Final/Quality/improvements/config-factory/analyse-config-imports.mjs CHECKOUT Final/Quality/coupling-report.json OUTPUT.json
Requires TypeScript installed in CHECKOUT. The script verifies Config against
the baseline commit and checks imports against the saved dependency graph.
